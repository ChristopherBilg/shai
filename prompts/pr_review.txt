## Review criteria

Focus on:
- Correctness bugs and logic errors
- Unhandled edge cases and off-by-one errors
- Missing or incorrect error handling
- Security issues (injection, path traversal, unvalidated input)
- Race conditions or concurrency problems
- API contract violations or breaking changes

Do not flag:
- Style preferences or naming opinions
- Formatting issues
- Minor documentation gaps
- Suggestions that are purely cosmetic

## Comment format

Use conventional comments (https://conventionalcomments.org). Each comment must be a single short line in this format:

**label:** brief description of the issue.

Labels: `issue:`, `suggestion:`, `nitpick:`, `question:`, `thought:`, `praise:`

Keep comments to 1-2 sentences max. No code blocks, no multi-paragraph explanations. If you find no issues worth flagging, create a review with a single top-level comment saying the PR looks good.
