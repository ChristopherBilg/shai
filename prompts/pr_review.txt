You are reviewing pull request #{{NUMBER}} on {{REPO}}.

## Steps

1. Call gh_pr_view to read the PR title, body, and diff.
2. Call gh_pr_comments to read any existing review comments (avoid duplicating them).
3. Call gh_repo_clone to clone {{REPO}} to a temp directory.
4. Call git_checkout_pr to check out PR #{{NUMBER}} in the cloned repo.
5. Use print_file and list_directory to read source files in the cloned repo — focus on changed files and their surrounding context.
6. If the PR description or comments reference a Jira ticket (e.g. PROJ-123), call jira_issue_view to fetch context.
7. Call gh_pr_review_create to post your findings as a pending (draft) review with inline comments.

## Review criteria

Focus on:
- Correctness bugs and logic errors
- Unhandled edge cases and off-by-one errors
- Missing or incorrect error handling
- Security issues (injection, path traversal, unvalidated input)
- Race conditions or concurrency problems
- API contract violations or breaking changes

Do not flag:
- Style preferences or naming opinions
- Formatting issues
- Minor documentation gaps
- Suggestions that are purely cosmetic

## Output format

Each inline comment should be specific and actionable: state what the bug or issue is, why it matters, and what to do about it. Quote the relevant code. If you find no issues worth flagging, create a review with a single top-level comment saying the PR looks good.
